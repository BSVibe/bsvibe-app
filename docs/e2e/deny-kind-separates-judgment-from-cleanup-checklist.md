# 거절의 두 행위를 가른다 — 검증 체크리스트

> 2026-09-09. 인수인계 §Ⅴ.a *"리뷰 피드백 경로 부재"* 를 재려다 나온 것이다.
> **그 항목은 결함이 아니었다** (경로는 A-1c 로 이미 있다). 대신 그 경로가
> **prod 에서 6번 발화했고 6번 다 잘못 발화한 것**이 드러났다.

## prod 실측 (`c852786`, 2026-09-08)

`deny` 는 동사 하나로 서로 다른 두 행위를 처리했고, **사유가 비어 있지 않기만
하면** 둘 다 지식이 됐다.

| 행위 | 형님이 실제로 쓴 문장 | 가르쳐야 하나 |
|---|---|---|
| **접근 거절** | *"답변이 코드 근거 없는 추론이다. 지시는 코드로 확인하고 근거 파일:라인을 대라 였다"* | ✅ |
| **큐 정리** | *"같은 런의 중간 스냅샷 — 최종 산출물 bb9b9664 에 포함됐다. **내용 문제 아님**"* | ❌ |

측정치:

* vault 의 `negative_pattern` 노트 **25건 중 11건이 큐 정리 문장** (3건은 `"probe"` 한 단어)
* 판사 계약 **58건**이 `Avoid (prior rejection)` 을 실었고, 그중 **10건이 큐 정리 문장**을
  판정 기준으로 실었다
* **2건은 "내용 문제 아님" 이라는 문장 자체**를 기준으로 실었다 — 형님이 *"내용 문제가
  아니다"* 라고 쓴 것이 다음 런을 **내용으로 심판하는 기준**이 됐다
* 가장 최근 런 `1515f44e` (09-08 01:45) 이 그중 하나다. 10건 중 5 passed / 5 failed —
  **큐 정리 기준이 그 실패의 원인이었는지는 미측정**
* 재개 경로도 같은 결함 — `_reopen_run_with_the_reason` 은 prod 에서 **6번 발화했고
  6번 다 큐 정리 거절**이었다 (2026-08-25). 큐 정리 문장이 *"Approve delivering this
  run's result?"* 의 **형님 답변**인 척 에이전트 맥락에 접혔다

⚠️ **측정 중 내 오측 하나** — 처음 센 값은 **0건**이었다. `contract` 는 JSON 텍스트라
한글이 `\uXXXX` 로 저장되고, 한글 `LIKE` 는 **영원히 0** 을 준다. `Avoid (prior
rejection)` (ASCII) 가 매칭돼서 쿼리가 도는 것처럼 보였다. **음성 대조군 없이 0을
믿을 뻔했다.** → `jsonb` 로 디코드해서 다시 셌다.

## 왜 지우지 않고 축을 더했나

형님 철학은 *더하기 전에 지워라* 다. 그래서 **"Safe Mode 교육을 통째로 지운다"** 를
먼저 쟀다:

* negative pattern **25건 중 22건이 Safe Mode 출신** (checkpoint 경로는 3건)
* 진짜 교육(*"답변이 코드 근거 없는 추론이다"*, *"지시가 조사만 하라였는데 파일 4개를
  고쳐 커밋했다"*)도 **전부 그쪽**

∴ 지우면 래칫이 죽는다. **축은 정당하다.** (A-1b 가 만들어진 이유이기도 하다 —
prod 실측 2026-08-16: 거절 91건, 서로 다른 런 67개, negative-pattern 행 0개)

## 선례가 이미 있었다 — 옮겨가지 않았을 뿐

커넥터는 **같은 이유로 이미 가르치지 않는다.** 폰의 거절 탭이 `declined via telegram`
을 사유인 척 넘기면 그것이 승격된다는 것을 알고 `reason=""` 을 넘긴다
(`backend/connectors/approval_callback.py`). **그 교훈이 형님이 직접 타이핑한 사유에는
옮겨가지 않았다** — 한 실패 경로에서 고친 교훈은 나머지로 안 옮겨간다.

## 새 형태

`DenyKind` 는 **필수**다. 기본값을 두면 한쪽이 조용히 틀린다:

* `QUEUE_CLEANUP` 기본 → 진짜 거절이 **조용히 안 가르친다**
* `REJECTED_APPROACH` 기본 → **오늘의 오염이 그대로 계속된다**

둘 다 침묵하므로 호출자가 **말해야** 한다. 누락은 422/TypeError 로 시끄럽게 실패한다.

| | 가르치나 | 런을 재개하나 | `deny_reason` 기록 |
|---|---|---|---|
| `rejected_approach` | ✅ (사유 있을 때) | ✅ (비종말 런) | ✅ |
| `queue_cleanup` | ❌ | ❌ | ✅ |
