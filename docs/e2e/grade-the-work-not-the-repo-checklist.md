# E2E — 등급은 작업을 보고 매긴다, 그리고 자동 진행이 조용하면 안 된다

대상: `honesty.work_is_gateable` + `_drive_loop` 래칫 + `_weak_evidence_sentence`.
검증 설계 SoT §8.5 / 백로그 항목 a·b(C4 흡수).

## 무엇이 틀렸었나

**C4** — `needs_founder_review` 가 `gate_expected = _manifest_present(repo)` 하나로 결정했다.
등급은 *이 작업*에 대한 판단인데 근거는 *레포*의 속성이다. 그래서 **똑같은 리포트가**
그 레포에 `pyproject.toml` 이 있느냐로 사람을 부르기도 하고 안 부르기도 했다 —
산출물이 검증 가능한지와 아무 상관 없는 기준. 결과: **비개발 산출물은 매번 형님을 불렀다.**

**a** — 그런데 파킹을 그냥 없애면 **조용해진다.** 지금까지 형님이 약한 증거를 항상 알았던 건
*방해받았기* 때문이다. 파킹을 걷어내면 "돌릴 게 없어서 못 정했다"를 말해주는 곳은
Delivery Report 뿐이고, 그건 **열어봐야** 보인다. 폰에 가는 알림은 "작업 완료" 한 줄이었다.
→ #742 의 교훈과 같은 자리: **런이 verified 로 끝난 것 ≠ 결과가 사람에게 도달한 것.**

∴ 둘은 한 PR 이다. **면제와 고지는 같이 가야 한다.**

## 라이브 검증

- [ ] **산문 작업이 더 이상 안 부른다** ⭐
      매니페스트 있는 레포(bsvibe-app)에 `.md` 만 나오는 작업 투입 →
      등급이 D 로 떨어져도 `execution_decisions` 에 `weak_evidence_no_gate` **0건**,
      런은 `review_ready`.
      ⚠️ **C1 덕분에 대개 B 를 받는다.** D 를 보려면 작업 문장에 검사 가능한 요건이
      없어야 한다(플래너가 빈 계획을 냄). 그게 안 잡히면 이 항목은 **미검증**으로 남겨라 —
      "안 불렀다"를 관측했다고 **면제 때문이라고 단정하지 마라.**

- [ ] **면제받은 런이 폰에서 그렇게 말한다** ⭐⭐
      그 런의 텔레그램/푸시 본문에 **"돌릴 검사가 없어 내용만 확인했어요 (증거 약함)"**.
      *이게 없으면 이 PR 은 형님을 안 부르는 대신 형님을 어둠에 두는 것이다.*

- [ ] **코드 작업은 여전히 부른다**
      같은 레포에 `.py` 가 나오는 작업이 등급 D 를 받으면 **파킹된다**(대조군).
      이게 깨지면 면제가 새는 것이다.

- [ ] **행이 스스로 설명한다**
      `verification_results.result` 에 `work_gateable` 이 있고, 산문 런은 `false`.
      (`gate_expected` 만 보고는 왜 리뷰를 안 갔는지 알 수 없다.)

- [ ] **A/B 등급엔 약한-증거 문장이 안 붙는다**
      강한 증거로 통과한 런의 요약·알림에 "증거 약함" 이 없다.

- [ ] **영어 워크스페이스도 받는다**
      `language=en` 에서 `Verified: by content only — no runnable check existed`.

## 되풀이 금지

- **면제는 고지와 함께만 넣어라.** 사람을 안 부르기로 했으면, 안 부른 이유가
  사람이 실제로 보는 자리(폰)에 있어야 한다.
- **`_shipped_detail` 은 접두사로 줄을 고른다**(`검증`/`Verified`/`Acceptance`).
  새 문장이 그 접두사를 안 쓰면 요약엔 있고 **알림엔 없다** — 테스트가 이걸 잡는다.
- `.txt` 는 산문이다. 기존 테스트가 `a.txt` 를 범용 파일로 쓰고 있었다 —
  C4 이후 그건 "게이트 불가 작업"이라 래칫 테스트의 주제가 바뀐다.
