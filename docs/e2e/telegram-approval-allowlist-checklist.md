# E2E 체크리스트 — 텔레그램 승인 권한 통일 (#1046)

**무엇**: 승인 권한 판정을 세 커넥터가 **한 함수**로 쓰게 하고, 텔레그램의
`chat_type == "private"` 강제를 없앤다. 결과로 **1:1/그룹 구분이 사라진다.**

> 🧭 **판정의 방향이 바뀌는 변경이다.** 초록만 세면 *"이제 그룹에서 된다"* 는 알아도
> *"아무나 되지는 않는다"* 는 모른다. 항목마다 **양성과 음성을 쌍으로** 건다.

## A. 배포 전 (로컬 — 완료)

- [x] 공유 규칙 `backend/common/approval_allowlist.py` — 10가지 입력을 파라미터로 단언
      (허용/거부, int·str 혼용, 키 없음, 빈 목록, 리스트 아님, 스코프 일치/불일치/미바인딩)
- [x] **규칙이 하나임**을 런타임으로 단언 — `backend/connectors/*_callback.py` 를
      **디렉터리에서 세어**(하드코딩 목록 아님) 각각이 공유 함수를 부르는지 확인 + 집합 크기 단언
- [x] 규칙이 `chat_type` 을 읽지 않는다 — **함수 소스**로 단언(모듈 독스트링은 내력을 적어야 하므로 제외)
- [x] 텔레그램: **허용목록에 있는 사람의 그룹 탭 → 승인됨**
- [x] 텔레그램: **허용목록에 없는 사람의 그룹 탭 → 거부**(음성 대조군)
- [x] 텔레그램: **허용목록 없는 계정 → 형님 본인도 거부**(fail-closed)
- [x] 슬랙·디스코드 기존 테스트 **전부 통과** — 공유 규칙 추출이 충실하다는 증거
- [x] 마이그레이션: 일회용 PG 에서 세 행으로 **세 판정**을 한 번에
      (씨 뿌릴 행 / 이미 목록 있는 행은 안 건드림 / github 무관) + downgrade 대조군
- [x] 절단 2회: fail-closed→fail-open 이 **세 커넥터 6칸**을 뒤집음(규칙이 진짜 공유됨) ·
      텔레그램만 옛 등식으로 되돌리면 **정확히 1칸**

## B. 배포 후 (prod)

- [ ] `alembic_version` = `telegram_approval_allowlist`
- [ ] **무중단 확인**: prod 텔레그램 계정의 `delivery_config` 에
      `authorized_user_ids: ["8242700007"]` 가 생겼고 `chat_id` 는 그대로다.
      ⚠️ 배포 전 값(`chat_id` 만 있음)을 같이 적어라
- [ ] **1:1 승인이 여전히 된다** — 딜리버러블 하나를 1:1 에서 승인. 이게 무중단의 증명이다
- [ ] **그룹방 승인이 새로 된다** — 그룹에 바인딩을 걸고 카드를 받아 탭.
      ⚠️ 형님 손이 필요하다(그룹방 생성 + 바인딩)
- [ ] **그룹에서 승인 버튼이 실제로 렌더되는지** — 09-22 인수인계가 *"안 쟀다"* 로 남긴 칸.
      눌러도 안 되는 버튼이 아니라 **되는 버튼**이어야 한다
- [ ] 음성 대조군: 허용목록에 없는 계정(있다면)에서 탭 → `권한` 안내

## C. 안 건드린 것 (의도)

- **"방에 있으면 권한"은 채택하지 않았다.** 형님이 처음 그렇게 말씀하셨으나, 슬랙 구현이
  그 안을 이미 기각해 뒀다(*"a channel card is tappable by any member"*). 허용목록만으로도
  그룹방이 열리고 구분이 사라지므로, 되돌릴 수 없는 승인을 방 멤버십에 걸 이유가 없다
- **배송 목적지 로직** — `selection`/`delivery_config` 병합(#1003)은 그대로
- **슬랙·디스코드의 스코프 바인딩**(`team_id`/`guild_id`) — 그대로 유지. 텔레그램은
  봇 토큰이 이미 스코프라 해당 축이 없다
