# E2E — PWA 이메일 가입 폼 (#937)

**대상 PR**: `/signup` 페이지 + `signUp()` 클라이언트 + `/login` 의 진입 링크
**짝**: PR #1004(백엔드 API). 이 PR 로 #937 게이트2 의 *"이메일 가입 **UI**/API 없음"* 이 닫힌다.

> 🚪 **문은 여전히 닫혀 있다.** Supabase 프로젝트의 이메일 가입이 꺼져 있어 백엔드가
> **403** 을 준다. 이 폼은 그 403 을 *"아직 안 열렸어요, 소셜로 계속하세요"* 로 보여준다 —
> **그게 오늘의 기본 경로**이지 예외가 아니다.

> ⚠️ **#959 를 먼저 확인하라.** 스위치를 올리는 것은 **가입 경로를 여는 일**이다.
> #959 §1(배경 경로 워크스페이스 스코프)은 닫혔지만, 여는 판단은 별개다.

## 단위 — 이미 통과 (9건)

### 클라이언트 `signUp` (4)
- [x] `POST /api/auth/signup` 에 email·password + **우리 오리진**의 `redirect_to` 를 보낸다
      (오픈 리다이렉트 방지 — 백엔드가 CORS 허용목록으로 검증한다)
- [x] 세션이 오면 **로그인된다**
- [x] **확인 대기면 아무도 로그인되지 않는다** ⭐ — 주소가 증명되기 전이고 백엔드는
      사용자 행을 **안 만든다**. 여기서 세션을 심으면 앱 전체가 그 거짓을 믿는다
- [x] 403(가입 비활성)은 **그대로 던진다** — 페이지가 보여줘야 한다

### 페이지 (5)
- [x] 입력한 자격이 `signUp` 에 그대로 간다
- [x] 세션이 오면 `/brief` 로 이동
- [x] **확인 대기면 "메일을 확인하세요" 를 보이고 이동하지 않는다** ⭐
- [x] 가입 비활성이면 **읽을 수 있는 안내**(`role="alert"`)
- [x] `/login` 으로 돌아가는 링크가 있다
- [x] **`/login` 에 `/signup` 진입 링크가 있다** — 없으면 라우트가 고아가 된다

### 전선 절단 2건 — 각각 **정확히 하나**만 빨개짐
- [x] 확인 대기에도 `/brief` 로 보냄 → "이동하지 않는다" 테스트
- [x] 에러를 삼킴 → "읽을 수 있는 안내" 테스트

## 배포 후 — 문이 닫힌 채로 확인할 수 있는 것

- [ ] `/login` 에 **"처음이신가요? 계정 만들기"** 가 보인다 → `/signup` 으로 간다
- [ ] `/signup` 에서 아무 이메일로 제출 → **"이메일 가입은 아직 열려 있지 않아요"**
      ⚠️ 스택트레이스나 "실패했어요" 가 뜨면 403 분기를 못 탄 것이다
- [ ] 그 상태에서 **소셜 로그인은 정상** 동작한다(이 PR 은 그 경로를 안 건드린다)
- [ ] `ko` / `en` 둘 다 문구가 나온다(키 12개 × 2 로케일)

## §미실행 — 스위치를 올려야만 볼 수 있는 것

체크 안 된 칸이 *"아직 안 봄"* 인지 *"못 봄"* 인지 구분되지 않으면 다음 사람이 같은
자리에서 또 멈춘다.

| 항목 | 왜 못 걸었나 | 대신 무엇이 지키나 |
|---|---|---|
| 실제 가입 → 확인 메일 → 링크 → 로그인 | **콘솔 스위치가 꺼져 있다.** 켜는 건 형님 손이고 #959 판단이 선행 | 단위 9건 + 전선 절단 2건 |
| 자동 확인(Confirm email OFF) 경로에서 `/brief` 진입 | 같은 이유 | 단위: "세션이 오면 `/brief`" |
| 이미 있는 이메일로 가입 시 문구 | GoTrue 설정에 따라 다르다(재발송 / 무응답). 켠 뒤 실측 | 없음 — **켠 뒤 확인할 것** |
| 비밀번호 최소 길이 | GoTrue 프로젝트 설정이 강제한다. 폼은 빈 값만 막는다 | 없음 — 켠 뒤 확인할 것 |
