## §0 — 오늘 한 줄: **측정 장치는 조용히 고장 난다 — 잴 때마다 장치부터 재라**

오늘 RLS 를 fail-closed 로 바꿔 무엇이 깨지는지 쟀다. **그 측정이 두 번 무효였고, 두 번 다
대조군이 잡았다.** 한 번은 근사한 거짓 숫자(*"20 failed → 0 failed"*)를 보고하기 직전이었다.

| 무효였던 이유 | 어떻게 드러났나 |
|---|---|
| 내 `psql` 이 `>/dev/null 2>&1` 로 **DDL 에러를 가렸다** | 정책을 다시 읽으니 `execution_runs` 는 여전히 fail-open |
| **테스트 하나가 마이그레이션을 돌려 정책을 원복**시켰다 (`tests/data/test_rls_pg.py`) | 런 **후** fail-closed 표가 6/6 → **0/6** |

⇒ 프로토콜: **런 전에도 런 후에도 `pg_policies.qual` 을 세고**, 둘 다 6/6 일 때만 그 회차를 쓴다.

## §Ⅱ — #964 는 전제가 틀려 있었다 (재측정 결과)

착수 전에 쟀더니 **이슈가 시킨 1순위가 이미 되어 있었다**(PR #1006, `96d764a`).

| 이슈가 적은 것 | 실측 |
|---|---|
| settle 에 스코프 두르기 = 1순위 | **이미 있다** — 네 루프 전부(settle·schedule·delivery·agent) |
| *"배치가 마지막 워크스페이스 GUC 아래 flush 된다"* | **아니다.** `workspace_session_scope` 는 나갈 때 GUC 를 **비운다** ⇒ 배치 커밋은 *빈* GUC |
| 트랜잭션 분할이 선행 작업 | **오늘 증상이 없다.** 네 루프 중 강제 표에 배치-보류 쓰기를 하는 게 하나도 없어 fail-closed 에서도 통과 |

⇒ 분할은 *미래 대비*이고, fail-closed 의 진짜 차단기는 딴 데 있었다(§Ⅲ).

⚠️ **내가 #964 코멘트에 적은 `execution_runs 48 · requests 24` 는 테스트 개수가 아니라
트레이스백 줄 수다.** 실제로는 20건 전부 *워크스페이스를 먼저 만드는* 테스트였고, 그래서

## §Ⅴ — 이 세션에서 값을 한 규율

* **🔬⭐⭐⭐ 측정 장치는 조용히 고장 난다 — 런 전후로 장치를 재라.** 오늘 두 번 무효였다(§0).
  `>/dev/null 2>&1` 은 명령의 실패를 지우고, **테스트가 내 실험 조건을 원복**시킬 수 있다.
  *"그럴듯한 숫자가 나왔을 때"* 가 대조군을 다시 볼 시점이다 — 나쁜 숫자는 의심하지만
  좋은 숫자는 안 의심하기 때문이다
* **🧪⭐⭐ 내 테스트가 다른 테스트를 깨뜨릴 수 있다 — 그리고 그건 제품 회귀처럼 보인다.**
  `DROP/CREATE POLICY` 는 ACCESS EXCLUSIVE 락이라 공유 DB 런과 부딪힌다. 2건 실패 →
  재실행 통과 ⇒ **내가 만든 flake**였다. 하마터면 내 제품 변경 탓으로 오진할 뻔했다.
  같은 명제를 **락 없이** 잴 길이 거의 항상 있다(여기선 "남의 GUC 를 박는다")
* **📏⭐⭐ 숫자를 인용하기 전에 그 숫자의 단위를 확인하라.** `grep | sort | uniq -c` 로 센
  `execution_runs 48` 은 **테스트 개수가 아니라 트레이스백 줄 수**였고, 나는 그걸 이슈에
  결함 분포처럼 적었다(§Ⅱ 에서 정정)
* **🔁⭐⭐ 절단해도 안 뒤집히는 방어를 하루에 두 번 만났다** — 브레드크럼의 "펼치기 전용",
  검색의 세대 가드. 둘 다 *"그 시나리오에선 두 동작이 같은 일을 한다"* 가 이유였다.
  **방어를 늘릴 때마다 끊어 보고, 안 뒤집히면 뒤집히는 자리를 만들어라**
* **🎭⭐ 기존 테스트가 깨졌는데 제품이 아니라 테스트가 틀린 경우.** `getContent={vi.fn()}` 이
  프로미스가 아닌 `undefined` 를 주고 있었고 **아무도 안 불러서** 여태 숨어 있었다.
  새 기능(자동 열기)이 그 스텁을 처음으로 불렀다
* **🔢⭐ 개수로 잘림을 추론하지 마라.** `len(results) >= limit` 은 *"딱 맞았다"* 와
  *"잘렸다"* 를 구분 못 하고, 서버 상한이 `limit` 보다 작으면 잘렸는데도 False 다.
  **자른 쪽이 값으로 말하게** 하라(`TreeSearch(results, truncated)`)
* **🧱⭐ 순차 PR 을 쌓으면 squash 머지가 뒤 PR 을 DIRTY 로 만든다.** 원본 커밋과 squash
  커밋이 다른 객체라 같은 내용인데도 충돌한다. 해소할 땐 **테스트 이름 집합을 main 과
  비교해 잃은 게 없는지 세라**(오늘 0건 확인). 그리고 이 레포는 **auto-merge 가 꺼져 있고**
  브랜치 보호가 최신 상태를 요구한다 ⇒ `gh pr update-branch` 후 CI 를 한 번 더 태운다
* **⏱⭐ watch 예산은 잡 소요 + 큐 여유로.** `lint-and-test` 는 실측 **24분**이다
* **🧯 배포 디렉터리에 커밋하지 않았다.** 네 PR 전부 워크트리에서 나왔다
