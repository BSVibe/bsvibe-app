## §Ⅰ — 🚨 #1017: 발급자가 둘인데 검증기가 하나였다

`bsvibe products list` 가 prod 에서 401. 이슈는 **설정**을 범인으로 지목했지만 아니었다.

`bsvibe login` 이 저장하는 건 Supabase 세션 JWT 가 **아니라 우리 임베디드 OAuth 의
ES256 액세스 토큰**이다 — `iss=https://api.bsvibe.dev` · `aud=bsvibe-app` ·
**`sub` 가 `UserRow.id`**(supabase_user_id 아님) · **`wsp` 클레임 보유**. PAT 와 같은 클래스다.

⇒ `USER_JWT_JWKS_URL` 을 우리 발급자로 돌리면 **PWA 가 죽고, CLI 는 `sub` 때문에 그래도 못 들어온다.**
**prod env 는 한 글자도 안 바꿨다.**

### ⭐ 그 한계는 이미 코드에 적혀 있었다

`backend/api/main.py`: *"Mounted outside the auth-gated v1 router **because that gate
accepts only a Supabase session JWT**"*. `/api/v1/oauth/pats` **한 라우터만** 게이트 밖으로
빼서 우회했고, 나머지 v1 은 그대로 막혀 있었다.
⇒ **"X 가 안 된다"를 만나면 "X 를 되게 하려고 메커니즘을 탈출한 곳"을 찾아라. 그 주석이 진단이다.**

### 무엇이 들어갔나

* `backend/api/bearer_auth.py` — 두 클래스를 받는 리졸버 하나. `iss` 로 **결정적 분기**
  (try-A-then-B 아님) · **런 스코프 토큰 거절** · **메서드별 스코프 게이트**(read/write) ·
  워크스페이스는 토큰의 **`wsp`**(멤버십은 검증하되 테넌트를 고르지 않는다)
* `backend/identity/access_tokens.py` — 서명 + `jti` 행(폐기·**행 만료**) 검증을 **발급자 쪽으로**.
  MCP · PAT · worker register · v1 이 **전부 이 하나**를 부른다
* 🔎 그 통합이 **실재하는 드리프트**를 닫았다: `workers_register_auth` 는 `revoked_at` 만 보고
  **행의 `expires_at` 은 안 봤다** ⇒ 수명이 줄어든 토큰으로 워커 등록이 됐다.
  **prod 에 그런 행이 실제로 있었는지는 안 셌다**

### prod 대조군 쌍 (읽기 전용) — 게이트를 **넓혔지 좁히지 않았다**는 증거

| 보낸 것 | prod 응답 |
|---|---|
| Supabase 클래스(가짜 서명) | `JWKS resolution failed…` ⇒ **Supabase 검증기가 그대로** |
| 우리 발급자 클래스(가짜 서명) | `invalid access token` ⇒ 새 경로 |
| 진짜 CLI 토큰 | **200 + 데이터** |

### 이슈의 덤 항목 둘 다 틀렸다

* `api.bsvibe.dev/oauth/jwks` 는 "빈 키셋"이 아니라 **404** — 그런 라우트가 **레포에 없다**
* `auth.bsvibe.dev` 는 **연결 자체가 안 되고**(curl `000`) **CLI 경로에 없다**
  (저장된 `issuer` 는 `https://api.bsvibe.dev`)
* 키 퍼블리시는 멀쩡했다 — `/.well-known/jwks.json` 이 내 토큰의 kid 를 그대로 준다

## §Ⅱ — 🚨 #1016: 워커 opencode 스토어가 형님 것이었다

### 이슈가 말한 손잡이는 데몬을 조종하지 않는다

`opencode_data_dir()` 는 격리/로그가 **찾아볼** 경로를 *유도*할 뿐이다(docstring 이 직접 말한다 —
*"Resolution **mirrors** the env the daemon was spawned with"*). 데몬은 `sanitized_subprocess_env()`
를 그대로 받는다. ⇒ 그 값만 바꿨다면 **워커는 A 를 격리하고 opencode 는 B 에 쓰는 split-brain.**

### 바이너리를 재서 찾은 진짜 손잡이

| 변수 | 무엇을 옮기나 | 판정 |
|---|---|---|
| `XDG_DATA_HOME` | 데이터 디렉터리 **통째** | 🚨 **안 된다** — 거기 **`auth.json`**(프로바이더 크리덴셜)이 산다 |
| **`OPENCODE_DB`** | **DB 파일만**(절대경로면 그대로) | ✅ 터진 그것만 가른다 |

⇒ `OPENCODE_DB=$BSVIBE_HOME/opencode/<worker>/opencode.db`.
**기본값이 안전한 쪽**(#978 의 `default_claude_config_dir` 관례) · **워커별** ·
이름은 `BSVIBE_WORKER_NAME` 으로 들어와 경로에 닿으므로 **한 세그먼트로 살균** ·
**손상 복구도 우리가 고정한 스토어**를 격리한다.

### prod 실측 (`6787b7e`, 워커 재시작 17:00:2x)

* 로그가 before/after 를 직접 보여준다 — 옛 줄엔 **`db_path` 가 아예 없다**
* **inode 세 개가 전부 다르다**: `61395957`(형님) · `106765961`(admin) · `106765957`(e2e)
* 공유 스토어는 워커 재시작 2대 + 모든 프로브를 거쳐 **mtime·크기 불변**
* 🎁 **덤: admin 워커의 serve 가 이제 뜬다.** 마지막 `opencode_serve_disabled` 는 `02:45:59Z`,
  재시작 후엔 **없다** — 두 데몬이 같은 SQLite 를 물던 게 원인이었다. **#970 한 줄이 원인째 사라졌다**
* ⚠️ **임시 조치(plist PATH 1.17.3 고정)는 이제 불필요하다.** 되돌리는 건 별건(#1014 측정이 1.17.3 기준)

### ⚠️ 양성 대조군이 오늘 약했다 (그리고 그걸 어떻게 메웠나)

호스트 셸과 워커가 **둘 다 1.17.3** — 치명적이게 만들던 **버전 스큐가 지금 없다.**
*"띄워도 멀쩡하다"* 는 **조건이 사라진 대조군**이다(띄워서 확인은 했고 멀쩡했다).
진짜 증거는 **inode/파일 무변화**다.

그래서 **원래 터졌던 그 지점을 직접 쳤다.** 라우팅 규칙 생성이 **권한 분류기에 막혀**
(정당한 차단 — prod 설정 쓰기) **우회하지 않고**, 워커와 동일한 `opencode.json`(ollama) +
`OPENCODE_DB` 스크래치 데몬으로 같은 조건을 재현:

| 잰 것 | 결과 |
|---|---|
| `session_message` insert | ✅ **2행**, `seq` = 1, 2 |
| `seq IS NULL` | **0건** — `NOT NULL constraint failed: session_message.seq` 가 **바로 이 컬럼** |
| 공유 스토어 | 무변화 |

## §Ⅱ.5 — 🔐 #1027: 확인하러 간 로그에서 **유효한 크리덴셜**이 나왔다

#1017 의 마지막 칸(*"PWA 로 실제 로그인한 세션의 v1 왕복"*)을 닫으려고 prod 로그를 봤다.
닫으려던 증거는 있었고(세션 JWT 로 친 v1 9종이 전부 200), **그 옆에** 이게 있었다:

```
GET /api/v1/events/stream?token=eyJhbGciOiJFUzI1NiIs…<전체 JWT>… → 200
```

| 잰 것 | 결과 |
|---|---|
| 내용 | 형님의 **Supabase 세션 JWT** — `aud=authenticated` · `sub` · **이메일** · provider id · `session_id` |
| 아직 유효한가 | 🚨 **유효** — `exp` 19:07 / 관측 18:08 |
| 얼마나 남나 | 🚨 `json-file`, `max-size` **없음** ⇒ **무제한 보존** |

**라우트가 아니라 로거다.** `?token=` 은 의도된 설계고(EventSource 는 헤더를 못 보낸다),
uvicorn 기본 액세스 로거가 full path 를 쿼리스트링째 찍는 게 문제였다.

⇒ `uvicorn.access` 에 필터. **파라미터 이름 목록을 쓰지 않았다** — 그건 내가 떠올린 철자만
증명한다. **모든 값을 지우고 키는 남긴다**: 목록 없이 완전하고, 내일 새 엔드포인트가 쿼리에
크리덴셜을 실어도 **나온 날부터** 덮인다.

### prod 실측 (`9fdb919`, 10:35:43)

* 그 라우트를 **직접 쳤다** — 유효한 세션이 필요 없다. **추적 마커**를 심어서
  *"안 보인다"* 가 아니라 *"내가 보낸 그것이 없다"* 를 쟀다: `PROBE1027` **0건**
* 로그: `GET /api/v1/events/stream?token=*** 401` · JWT 그대로 찍힌 줄 **0건**
* ⭐ **그 0 이 의미 있다는 대조군**: `workers/poll?count=***` — 쿼리 요청이 **실제로 흐른다**
* 프로브가 401 — 리댁션은 **로그만** 건드린다

### 별건 (안 했다)

* **로그 로테이션**(`compose.prod.yaml` `max-size`/`max-file`) — **2층**이다.
  로테이션은 유출을 막지 못하고 **보존만 제한**한다
* **과거 로그에 남은 것** — 만료됐지만 PII 는 남아 있다. 잘라낼지 판단 필요

## §Ⅲ — #967 flake: 이번 에러가 판정표 한 칸을 지운다

PR #1023(문서 1개 파일)에서 `test_client_worker_manager::test_read_file_returns_contents` 실패.
**동일 코드가 20분 전 #1022 CI 에서 통과** ⇒ 재현 조건상 flake 확정, 재실행하니 통과.

```
exec timed out after 90.0s (command budget 30.0s + 60.0s report slack;
                            46 polls in 90.0s, last status 'dispatched')
```

#967 은 *"그 에러는 '하네스 굶음'과 '행이 안 보임'을 구분 못 한다"* 고 적었는데,
**`46 polls / 90s` (≈2초에 한 번)** 는 **폴링하는 쪽이 굶지 않았다**는 뜻이다.
남은 것은 *행이 안 보였다* / *워커 쪽이 굶었다* 둘 — **판정표에 폴 횟수 칸을 넣으면 한 칸이 준다.**
그 둘을 가르려면 **CI 가 워커 로그를 아티팩트로 올리는 것**(#950)이 선행이다.

## §Ⅵ — 이 세션에서 값을 한 규율

* **🎛⭐⭐ 설정 슬롯 하나에 정당한 생산자가 둘이면, 설정은 해법이 아니다.** 값을 바꾸는 건
  **죽는 쪽을 바꾸는 것**뿐이다. 착수 전 30초: *제안된 수정을 한 칸 앞으로 돌려봐라* —
  다른 클라이언트가 여전히 통과하나? 통과한 뒤 **다음 층**이 그 principal 을 쓸 수 있나(식별자 공간이 같나)?
  스킬 `a-config-slot-cannot-hold-two-legitimate-producers`
* **🪤⭐⭐ "X 가 안 된다"를 만나면 X 를 되게 하려고 메커니즘을 탈출한 곳을 찾아라.**
  `main.py` 의 마운트 주석이 #1017 의 진단을 **이미 문장으로** 들고 있었다.
  **한 라우터만 게이트 밖에 있으면 그건 스타일이 아니라 상처다**
* **🔌⭐⭐ 설정이 "읽힌다"와 "그 설정이 대상을 조종한다"는 다른 명제다.** `opencode_data_dir` 은
  읽히지만 데몬을 안 움직인다. **무엇을 스폰하는 코드의 `env` 를 직접 봐라** — docstring 이
  *"mirrors"* 라고 말하면 그건 조종이 아니다
* **🧪⭐ 격리가 대조군의 조건을 지운다.** 스토어를 가르고 나니 *"opencode 를 띄워도 멀쩡"* 이
  약해졌다 — 버전 스큐가 없어서다. **대조군을 쓰기 전에 "치명적이게 만들던 조건이 아직 있나"를 물어라.**
  없으면 **결함이 살던 지점 자체**(여기선 `session_message` insert)를 직접 쳐라
* **📏⭐ 내 탐지기의 대상 집합이 두 스냅샷 사이에 달라지면 거짓 경보가 난다.** glob 이 `.bak-*`
  까지 잡아 🚨를 찍었다. **diff 전에 두 스냅샷이 같은 집합인지부터 봐라.** 고정 파일 목록을 써라
* **🧷⭐⭐ FastAPI 의존성의 부모를 바꾸면 `dependency_overrides` 씸이 같이 옮겨간다.**
  29개가 한 모양(`missing Authorization header`)으로 깨졌다 — 기능이 아니라 **씸**이다.
  해법은 새 데이터를 `request.state` 로 **발행**하고 하위가 비침습적으로 읽는 것:
  오버라이드된 경로는 **리팩터링 전 동작으로 자연 폴백**한다.
  스킬 `re-parenting-a-dependency-moves-the-test-override-seam`
* **🧱⭐⭐ 계층 계약의 거절은 그 로직이 어디 살아야 하는지를 말한다.** `ignore_imports` 도
  lazy import 도 답이 아니었다(import-linter 는 함수 레벨도 본다). **발급하는 쪽이 검증도 소유한다** —
  Identity 로 내리니 호출자 셋이 채택할 수 있게 됐고 **그중 하나가 이미 드리프트해 있었다**.
  스킬 `a-layering-contracts-refusal-names-the-right-home`
* **🔪 절단이 또 갈랐다.** 두 PR 합쳐 **10회**, 전부 컴파일됐고 **정확히 의도한 테스트만** 뒤집었다.
  특히 #1016 의 `XDG_DATA_HOME` 절단은 **설계 가드가 초록만 낼 수 있는 검사가 아님**을 증명했고,
  #1017 의 행-만료 절단은 **MCP 테스트까지 같이 빨개져** 검증기가 실제로 공유임을 증명했다
* **🚫 막힌 게 정당하면 우회하지 마라 — 덮을 다른 측정을 찾아라.** 라우팅 규칙 쓰기가 막혔을 때
  prod 를 건드리는 우회 대신 **결함이 살던 지점**을 스크래치에서 직접 쳤다
* **🔎⭐⭐ 확인하러 간 자리에서 다른 결함이 나온다.** #1017 의 마지막 칸을 닫으려고 prod
  로그를 열었더니 **유효한 세션 JWT** 가 거기 있었다(#1027). 검증은 그 명제만 재는 게 아니라
  **그 표면을 처음 제대로 보는 일**이다 — 읽는 김에 **옆줄도 읽어라**
* **🔪⭐ 절단이 초록이면 가드를 의심하기 전에 절단을 의심해라.** #1027 의 세 번째 절단이
  안 뒤집혔는데, 가드가 약한 게 아니라 **내 치환이 사실상 같은 동작**이었다 —
  *컴파일은 되는데 아무것도 되돌리지 않은 절단*. [[a-cut-that-does-not-compile-is-not-a-wire-cut]] 의 사촌
* **🧪⭐ 0 을 보고할 땐 생산자가 켜져 있었는지 같이 보고해라.** #1027 실측의 "JWT 0건" 은
  `workers/poll?count=***` 라는 **살아 있는 쿼리 트래픽**이 있어서 의미가 생겼다.
  그리고 **추적 마커**(`PROBE1027`)를 심으면 *"안 보인다"* 가 *"내가 보낸 그것이 없다"* 가 된다
* **🧯 내가 또 배포 디렉터리 `main` 에 직접 커밋했다.** 브랜치로 옮기고 `origin/main` 으로 되돌렸다.
  **워크트리는 편의가 아니라 안전장치다** — 문서 한 줄이라도 PR 을 거쳐라
