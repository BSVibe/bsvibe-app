## §Ⅰ — 삭제는 **읽는 쪽**만 지우면 안 끝난다

#924(09-11)는 `trigger.enabled` 를 지웠다고 적었다. prod 실측(착수 전):

| | |
|---|---|
| `resource_bindings` 3행 | **전부** `{"enabled": false, "filters": {}}` |
| `72a32df5…` | **09-18 04:00 UTC** 생성 — 삭제 **일주일 뒤** |

범인 특정은 **소거법**이었다. `audit_outbox` 에 `bsvibe.mcp.*` 이벤트가 **0건**이고
(5,571행 전부 execution/ontology — 선언된 `audit_event` 가 거기 안 간다), 그래서:

* **PWA 는 아니다** — create 가 `trigger`·`selection` 을 안 보내는데 그 행은 `selection` 이 차 있다
* **REST 는 아니다** — `TriggerKnob(extra="forbid")` 가 거절한다(로컬 대조군으로 실증)
* ⇒ **MCP 만 남는다.** 거기만 `trigger: dict[str, Any]` 였다

그리고 **툴 설명**이 `({enabled, filters})` 를 11일간 광고하고 있었다.
⇒ 메뉴가 죽은 키를 권하고, 스키마가 그걸 받았다. **한 문의 두 짝**이다.

## §Ⅱ — ⭐ 가드를 쓰다가 내 손으로 결함을 재현했다

제거 내력을 `TriggerKnob` **클래스 독스트링**에 적었더니, 새로 만든
*"메뉴에 죽은 키가 없는가"* 가드가 **빨개졌다**. pydantic 클래스 독스트링은
**그대로 MCP 와이어 스키마의 description** 이다 — 에이전트가 읽는 그 문장.

⇒ **폐기된 이름은 모듈 독스트링에, 개발자용 메모는 주석에.** 주석은 스키마에 안 실린다.
(배포본에서 확인하니 개발자용 ⚠️ 메모 한 줄이 실제로 스키마에 실려 나가 있었다 — 이 PR 에서 뺐다.)

## §Ⅲ — 🚨 형님 UI 가 11일간 깨져 있었고, 테스트가 그걸 덮고 있었다

`ProductBindings` 의 `Trigger on` 체크박스:

* `row.trigger.enabled` 를 읽는데 프로덕션은 그 키를 더는 안 준다 ⇒ **항상 꺼짐**으로 보인다
* 켜면 PATCH 가 REST 의 `extra="forbid"` 에 걸려 **422** ⇒ `changeError` 만 뜬다

**유닛 픽스처가 프로덕션이 안 주는 키를 넣어 주고 있었다**(`trigger: { enabled: false, … }`).
그래서 깨진 UI 가 802 테스트 속에서 초록이었다. 스킬 `unit-test-supplies-what-production-withholds`.

**컨트롤을 지웠다**(되살리지 않았다) — #924 의 판단대로 *"반응하나"* 는 `filters` 가 말한다.
⚠️ **`filters` 의 UI 는 여전히 없다.** 형님이 바인딩별 on/off 를 원하시면 **새 기능**이고,
#924 가 *"켜는 순간 라이브 바인딩이 전부 꺼진다"* 를 이유로 안 만든 노브라 **기본값 방향부터**
새로 정해야 한다.

## §Ⅵ — 이 세션에서 값을 한 규율

* **🗑⭐⭐ 삭제는 읽는 쪽만 지우면 안 끝난다 — 쓰는 쪽을 전수로 세라.** #924 는 소비자를
  지우고 끝냈고, 생산자 셋이 11일을 더 살았다. 센서는 **삭제 이후에 태어난 행**이다
  (09-18 행 하나가 "아직 안 끝났다"를 혼자 증명했다). 감사 이벤트가 없어 **소거법**으로
  좁혔다 — 쓰기 경로를 하나씩 닫아 보면 남는 게 범인이다
* **📋⭐⭐ 클래스 독스트링은 에이전트가 읽는 메뉴다.** pydantic 클래스 독스트링이 그대로 MCP
  와이어 스키마의 description 이 된다. **폐기된 이름의 내력을 거기 적으면 메뉴로 돌아온다** —
  거절한다고 적어도 마찬가지다. 내력은 모듈 독스트링에, 개발자용 메모는 주석에
* **🎭⭐⭐ 픽스처가 프로덕션이 안 주는 것을 넣어 주면 UI 가 깨진 채로 초록이다.** 체크박스가
  11일간 422 를 뱉는데 802 테스트가 전부 통과했다. 스키마를 바꿨으면 **픽스처부터** 따라와야 한다
* **🚫⭐ 부재 가드의 철자는 내 상상력이고, 언어 경계는 그 상상력의 벽이다.** 기존 가드는
  `'"enabled"'` **한 철자**만 봐서 툴 설명의 `({enabled, filters})` 를 놓쳤고, **PWA(TS)는
  표면 목록에 아예 없었다.** 고치면서 배운 것: **코드와 산문을 갈라야** 가드가 자기 설명에
  걸려 빨개지지 않는다(그러면 다음 사람이 가드를 느슨하게 만든다). 스트리퍼에도 대조군을 붙였다
* **📏⭐ 배포 후 0 을 보고할 땐 배포 전 분모를 같이.** `3/3 → 0/3` 이라 써야 말이 된다.
  기준선은 **머지 전에** 떠야 한다 — 배포된 뒤엔 다시 못 뜬다
* **🚫📏⭐ 대조군이 0 이면 그 프로브는 아무것도 안 쟀다.** 배포된 PWA 번들에서 `Trigger on`
  0건을 봤는데 **양성 대조군 `Output mode` 도 0건**이었다 ⇒ 그 표면이 애초에 그 청크에 없다.
  대조군을 안 걸었으면 "확인했습니다"로 보고할 뻔했다
* **🧪⭐ skipped 는 passed 가 아니다 — 일회용 컨테이너를 띄워라.** `test_alembic_fresh.py`
  14건이 로컬에서 **전부 skip** 이라 마이그레이션이 실증 0인 채로 나갈 뻔했다. 일회용
  pgvector 를 5459 에 띄워 14건을 실제로 돌렸다(**prod DB 는 읽기 전용 조회만**)
* **🔪 절단 4회, 전부 컴파일, 각각 5·2·1·1 칸.** **설명만** 되돌렸을 때 스키마 테스트가
  초록이었던 것이, 네 층이 서로를 대신 증명하지 않는다는 증거다
* **🧱 아키텍처 계약이 집을 알려줬다.** `TriggerKnob` 을 `backend/common/` 으로 올리자
  `lint-imports` 6 계약 전부 KEPT — 그 디렉터리에 `connector_redaction` 이 **똑같은 이유로**
  이미 있었다(미러가 어긋나 응답에 라이브 크리덴셜이 나갔다). 선례를 먼저 찾으면 예외를 안 판다
* **🧯 배포 디렉터리에 커밋하지 않았다.** 두 PR 전부 워크트리에서 나왔다
