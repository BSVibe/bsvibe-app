## §Ⅱ — #970 경고 2: 이슈가 *"못 끄면"* 이라고 쓴 건 **끌 수 있는지를 안 재서**다

매 CLI 호출이 stderr 로 찍던 줄:

```
⚠ claude.ai connectors are disabled because ANTHROPIC_API_KEY or another auth source is set …
```

방아쇠는 `ANTHROPIC_AUTH_TOKEN` 이 **설정돼 있다는 사실**이고, 워커가 **일부러** 넣는 것이다
(launchd 로 뜬 claude 가 Keychain 을 못 읽는다). ⇒ **설계대로 동작 중임을 알리는 경고**였고,
두 번의 조사에서 *"인증 경로가 엉뚱한 가지로 갔다"* 로 읽혀 시간을 썼다.

### ⭐ 번들에서 **그 문장의 가드를 직접 읽었다**

내가 떠올린 철자를 grep 한 게 아니다. 경고는 `api_key_precedence` 분기에서 세팅되고,
**그 앞에 early return** 이 있다 — `disableClaudeAiConnectors`(설정) 또는
`ENABLE_CLAUDEAI_MCP_SERVERS`(env). 앞의 것을 골랐다: 우리가 **이미 `--settings` blob 을
들고 있고**, CLI 의 env 는 형님 쪽 blast radius 다.

### 실측 — 노브가 **양방향으로** 뒤집힌다

| 잰 것 | stderr |
|---|---|
| (노브 없음) | ⚠️ 나온다 — **양성 대조군** |
| `disableClaudeAiConnectors=true` | **없다** |
| `disableClaudeAiConnectors=false` | ⚠️ 나온다 — **대조군** |
| `ENABLE_CLAUDEAI_MCP_SERVERS=0` / `=false` | **없다** |
| `ENABLE_CLAUDEAI_MCP_SERVERS=1` | ⚠️ 나온다 — **대조군** |

토큰 **값**은 무관하다고 #970 이 이미 실측했으므로 **더미**를 썼다 — 진짜 refresh 토큰은
**단발성**이라 디버깅으로 태우면 안 된다.

### 🚨 툴 도착이 안 깨지는지를 따로 쟀다

워커의 치명적 실패 모드가 *"BSVibe 툴이 안 왔다"*이다. 스크래치 stdio MCP 서버 + 실제
스트리밍 경로로 노브 on/off 각각 `system/init` 을 읽었고 **양쪽 다 `connected` + 툴 존재**.

### 배포 후 실측 (prod `ac05dd7`, 워커 11:47:47)

* 배포된 코드의 **실제 argv** 를 찍었다(`_build_cmd` — 체크리스트가 적어 둔
  `_build_cmd_args` 는 **없는 이름**이었다). 두 분기 모두 키를 싣는다
* 그 argv 그대로 / **그 키만 뺀** 쌍: **없음 vs 경고 복귀.** 없음만 재면 무엇을 껐는지
  증명이 안 된다
* ⭐ **실제 agentic 런**(`faa6b80c`, 11.8초) — **완주는 툴 도착의 증거가 아니다.**
  이 워커에는 툴이 없을 때 **툴 호출을 산문으로 흉내 내고 결과를 지어낸** 전력이 있다.
  그래서 과제를 *"`bsvibe_work_file_read` 로 `docs/HANDOFF.md` 첫 줄을 읽고 **그대로 인용**하라,
  못 읽었으면 **지어내지 말고** 못 읽었다고 적어라"* 로 잡았고, 산출물이 그 줄을 그대로
  인용했다 ⇒ **prod 원격 MCP 서버** 조건이 닫혔다

## §Ⅲ — #1003: 만들려던 키가 이미 있었다

`delivery_config` 는 **커넥터 계정**의 것이라 한 봇에 묶인 모든 제품이 같은 방으로 갔다.

내가 처음 낸 메뉴는 *"바인딩에 **새 전용 키**(마이그레이션 1건)"* 였고 형님이 그걸 고르셨다.
**그 직후 prod 를 조회하니 그 키는 이미 존재했고 세 행 모두 채워져 있었다:**

| 바인딩 `selection` | 계정 `delivery_config` |
|---|---|
| `{"chat_id": "8242700007"}` | 동일 |
| `{"chat_id": "8242700007"}` | 동일 |
| `{"repo": "BSVibe/bsvibe-app", "base_branch": "main"}` | 동일 |

`_resolve_bindings` 가 `connector_account_id` **만** select 해서 닿은 적이 없었을 뿐이다.
⇒ 메뉴를 되돌리고 다시 여쭤 **있는 걸 읽는** 쪽으로 갔다. 마이그레이션 **0건**.

### 들어간 것

* 디스패치가 `{**account.delivery_config, **binding.selection}`. 좁은 쪽이 나중
* **소비 지점이 둘**(이벤트 빌더 · 플러그인 컨텍스트) — 한 이름을 계산해 둘이 같이 읽는다.
  테스트 지렛대도 둘로 갈랐다: `chat_id` 는 빌더를, `telegram_api_url` 은 **빌더를 안 거치고**
  플러그인이 `ctx.config` 에서 읽으므로 **요청이 어느 호스트에 떨어지는가**가 두 번째 지점의 증언
* **(제품, 계정) 유니크 제약이 없다** ⇒ 행 둘이 다른 방을 가리키면 **오버라이드를 버리고**
  계정 설정을 쓴다. 배송은 되돌리기 어려우니 추측하지 않는다. **값이 같은 중복은 정상 적용**
* 🧱 400 LOC 가드에 걸려 `_destination.py` 로 갈랐다(우회 안 함). 김에 **그 가드가
  하드코딩 목록 6개인데 패키지엔 8개**여서 `_github_pr.py`·`_github_in_place.py` 가
  **애초에 캡 밖**이던 것도 디렉터리 전수로 닫았다
* **github 는 범위 밖.** `deliver_github` 는 `GithubBinding` 을 받고 그건 **제품 자신의
  `repo_url`** 로 계정을 고른다(#681/#684/#723) — `resource_bindings` 를 아예 안 본다

### 승인 탭 = **형님 결정 C (문서화)**

`chat_id` 하나가 *"어디로 보내나"* 와 *"누가 승인할 수 있나"* 를 겸하고, 1:1 에서만 성립하는

## §Ⅵ — 이 세션에서 값을 한 규율

* **📏⭐⭐ 백로그 항목은 착수 전에 다시 재라 — 이미 사라졌을 수 있다.** 어제 문서가
  *"그대로다"* 로 넘긴 #970 경고 1 은 **원인째 없어져 있었다.** 재는 데 5분,
  안 쟀으면 없는 걸 고쳤다. ⚠️ 그리고 **0 을 보고할 땐 생산자가 켜져 있었는지 같이** —
  `claude_oauth_refreshed` 12건이 그 0 을 의미 있게 만든다
* **🗄⭐⭐ "새 설정 키가 필요하다" 전에 prod 행을 조회하라.** #1003 의 슬롯은 이미 있었고 이미
  채워져 있었다. **grep 은 "독자 없음"을 증명하지 "무용함"을 증명하지 않는다** — 자유형 JSON
  칸은 **쓰는 쪽이 읽는 쪽보다 먼저 생기는 게 정상**이다. 센서는 **같은 값의 사본 개수**
  (`resource_id`·`selection`·`delivery_config` 세 벌이면 새 키는 **네 번째**).
  스킬 `a-populated-column-with-no-reader-is-a-missing-consumer`
* **💰⭐⭐ 내가 낸 메뉴의 "대가" 칸도 검증 대상 주장이다.** 선택지가 *무엇을 하는지*는 코드로
  쟀는데 **가격표를 안 쟀다.** 형님은 틀린 숫자로 결정하셨고 다시 여쭤야 했다.
  **"새로 만들어야 한다"는 대가가 참이려면 "이미 없다"를 세었어야** 한다 —
  그건 코드가 아니라 **데이터**에 있다. 그리고 오늘은 추천안이 *말한 것보다 쌌는데*,
  **싸게 틀려도 사고다**(안 골랐을 수도 있다)
* **🚫⭐ "못 끄면 문서화" 라고 적힌 칸은 대개 끌 수 있는지를 안 잰 것이다.** 벤더 CLI 는
  노브를 `features list`·설정 키에 숨긴다. **번들에서 그 문장의 가드를 직접 읽어라** —
  경고 문자열을 grep 하면 내가 떠올린 철자만 증명한다
* **✅⭐⭐ 초록 완주는 "툴이 왔다"를 말하지 않는다.** 툴이 없으면 이 모델은 **호출을 산문으로
  흉내 내고 결과를 지어낸다.** 검증 런은 *"읽어서 **그대로 인용**하라, 못 읽었으면
  **지어내지 말고** 그렇게 적어라"* 로 잡아라 — **인용된 문자열이 도착의 증거**다
* **🔪 절단이 또 갈랐다.** 두 PR 합쳐 **8회**, 전부 컴파일됐고 의도한 칸만 뒤집혔다.
  특히 #1003 의 **호출 지점별 절단 둘**(빌더만 / 컨텍스트만)이 각각 **하나씩만** 뒤집혀,
  한 상수를 공유해도 **호출자 배선은 따로 증명된다**는 걸 보였다
* **🧱⭐ 아키텍처 가드의 거절은 집을 알려준다 — 그리고 그 가드가 새고 있을 수 있다.**
  400 LOC 캡이 `_destination.py` 를 만들게 했고, 그 캡의 **하드코딩 목록이 이미 두 파일을
  빠뜨리고** 있었다. **목록 말고 디렉터리를 세라**(그리고 전수의 크기 자체도 단언하라 —
  전수가 비면 아래 전부가 **안 돌아서** 통과한다)
* **🧪⭐ push 전엔 CI 워크플로의 명령 목록을 그대로 돌려라.** 내 루틴은 ruff+pytest 셋이었고
  CI 는 **다섯**(+`lint-imports`, +`mypy backend/`)이라 mypy 로 한 번 빨개졌다.
  ⚠️ 이건 **이미 기억에 있던 함정**인데 인덱스에 **파일명만** 있어 결정 순간에 안 보였다.
  그리고 거기 적힌 명령은 **CI 의 실제 명령이 아닌 재구성**이었다 — 재구성은 재현이 아니다
* **📦⭐ 밀린 잡일은 "몇 편인지"부터 틀린다.** Notion 아카이브가 **일곱 세션** 밀려 있었는데
  어제 헤더는 여섯이라 적어 놨고, 나도 그 숫자를 그대로 옮겨 적었다. `git log -- docs/HANDOFF.md`
  로 세니 일곱이었다. **밀린 것의 개수는 그걸 미룬 문서가 아니라 원본에서 세라** —
  미룬 문서는 자기가 미룬 걸 세는 주체로는 최악이다
* **🧯 이번엔 배포 디렉터리에 커밋하지 않았다.** 세 PR 전부 워크트리에서 나왔다
