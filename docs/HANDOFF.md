## §Ⅱ — 설계에서 정한 것 (다음 사람이 뒤집지 말 것)

* **`'*'` 는 필요한 한 줄만 감싼다.** `WITH CHECK` 는 `'*'` 를 **지금 이미** 거절한다 — 세션째 감싸면
  스코프 밖 쓰기(예: settle 의 embed 훅)가 prod 에서 바로 터진다. 열린 트랜잭션엔 `cross_tenant_session_read`,
  새 세션엔 `cross_tenant_read()`
* **클레임 모양**: 한 트랜잭션에서 `'*'` 로 `SELECT … FOR UPDATE SKIP LOCKED` → 행마다 테넌트 스코프 `UPDATE` → 커밋.
  락이 커밋까지 가므로 SKIP LOCKED 의미는 그대로. `_reap_stale_claims` 는 이제 잠긴 행을 **건너뛴다**(전엔 기다렸다)
* **웹훅은 핸들러가 스코프를 갖는다** — Discord 는 응답 뒤 백그라운드 작업에서 자기 세션으로 핸들러를 부른다
* **rollback 이 객체를 만료시킨다** — 교차 스캔 결과를 루프에 들고 다니지 말고 `(id, workspace_id)` 만 꺼내 스코프 안에서 다시 잡아라

## §Ⅴ — 이 세션에서 값을 한 규율

* **🔬⭐⭐⭐ 측정 장치의 양성 대조군은 결과 집합 안에서 찾아라.** 「0」이 나오면 좋은 소식이기 전에 **반드시 있어야
  할 한 건**을 찾아라. 롤백으로 끝나는 세션은 같은 트랜잭션의 기록까지 지운다 — 로그는 트랜잭션 밖(`RAISE LOG`)으로
* **✂️⭐⭐ 절단 매트릭스는 지점마다.** 7개 PR 전부 호출 지점 N 개 = 절단 N 개, 각자 **자기 테스트만** 빨갛게 되는지 봤다.
  한 단언이 먼저 걸려 다른 단언이 이빨이 있는지 가려지면, 앞 단언을 빼고 **다시 끊어라**(#1070)
* **⏳⭐⭐ 동시성 보장은 「막힘 vs 건너뜀」을 가르는 테스트로.** `gather` 로 두 워커를 돌려 겹침 없음만 보면
  `FOR UPDATE` 만으로도 초록이다. 한 세션이 행을 잡은 채로 바운드 안에 돌아오는지 봐라(#1071 홀드 테스트)
* **🧪⭐ 측정 장치가 자기 헬퍼를 센다** — 검증용 조회는 스냅샷 **뒤**에(#1071 `_statuses`)
