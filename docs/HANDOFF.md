증거 전량은 **[#965 코멘트](https://github.com/BSVibe/bsvibe-app/issues/965#issuecomment-5690690251)** 에 있다.

`tccd` 가 동의 창을 띄우기로 결정하는데, launchd 잡에는 그 창에 답할 세션이 없다 ⇒ 요청이 영구
pending ⇒ 그 사이 CLI 의 `openat` 이 영원히 반환되지 않는다 ⇒ 침묵 ⇒ 백엔드 300초 타임아웃.

### 형님 조치 — 책임 바이너리 **둘 다** 전체 디스크 접근 권한

시스템 설정 → 개인정보 보호 및 보안 → **전체 디스크 접근 권한**. TCC 는 launchd 잡의 **맨 위
프로세스**에 책임을 귀속시키는데, 워커 셋이 둘로 갈린다:

| 워커 | ProgramArguments | TCC 책임 바이너리 |
|---|---|---|
| `com.bsvibe.worker`, `-admin` | `/opt/homebrew/bin/uv run python -m …` | `/opt/homebrew/Cellar/uv/0.10.4/bin/uv` |
| `-mac-mini-e2e` | `.venv/bin/bsvibe-worker run` | `~/.local/share/uv/python/cpython-3.11.14-macos-aarch64-none/bin/python3.11` |

⚠️ **"plist 에서 `uv run` 을 빼면 된다"는 이미 반증됐다.** 09-15 케이스의 책임 바이너리는 uv 가
아니라 **그 CPython** 이었고 똑같이 프롬프트가 떴다. 둘 다 서명 없는 바이너리라 **런처를 바꾸면
경로만 옮겨 간다.**

**권한 부여 후 검증**: 최소 런을 다시 쏴서 `executor_turn_first_event` 가 뜨는지 본다. 그게 유일한
통과 증거다. 그 다음 **#966 체크리스트 3번**(긴 `act` 턴이 안 잘린다)을 **같은 런에서 반드시** 확인할 것.

### 아직 모르는 것 (정직하게)

claude 가 **정확히 어느 경로**를 열다 NetworkVolumes 정책에 걸리는지는 못 짚었다 — `tccd` 는
service 만 남기고 경로를 안 남긴다. 유일한 automount 는 `auto_home`(`/System/Volumes/Data/home`)
인데 워커 PATH·cwd 어디에도 없다. **권한을 주면 증상은 사라지지만 트리거 경로는 미상으로 남는다.**

## §Ⅴ — 이 세션에서 값을 한 규율

* **🚨 `log` 는 zsh 빌트인이다.** `log show …` 가 조용히 `too many arguments` 로 죽어 **모든 TCC
  쿼리가 0줄**을 반환했다. **양성 대조군(전체 줄 수)을 안 셌으면 "TCC 아님"으로 오판**하고 진짜
  원인을 지나칠 뻔했다. `/usr/bin/log` 절대경로를 써라 — 그리고 **0줄은 "없음"이 아니라 "계측기가
  죽었을 수도 있음"이다**
* **⏱ 타임아웃 난 프로세스는 죽기 전에 심문해라.** `lsof`(소켓 0개) · `sample`(openat 100%) ·
  `ps -Ewwo`(env 전량) 셋이 **살아 있는 동안에만** 얻어진다. 로그만 읽었으면 영원히 못 찾았다
* **🔬 "재현이 안 된다"는 재현 조건을 아직 못 베꼈다는 뜻.** 셸 replay 가 계속 성공한 건 argv·env 를
  베꼈지 **누가 띄웠는가**를 못 베꼈기 때문이다. **환경을 복사할 때 부모도 환경이다**
* **🩺 배제도 산출물이다** (직전 판에서 이어받음) — 직전 여섯 개 덕에 네 개만 더 지우고 도달했다
