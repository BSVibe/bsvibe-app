# 툴 표면 — 결정 지점을 없앤다

> **형님 (2026-08-19)**: *"저게 왜 필요해? 어차피 검증에서는 read only라서 이슈 크지 않을 듯
> 한데. 애초에 이미 workspace에 종속되어서 일하는 유저, 워커잖아. 저거 자체의 필요성을 모르겠어"*
>
> 맞다. **이 문서는 세 번째 판이고, 앞의 둘은 폐기됐다.**
> `Inspect_Only_Path`(라벨 추가) → `Run_Capabilities`(능력 enum) → **이 문서(결정 삭제)**
>
> 매 판마다 내가 무언가를 **더하려** 했고, 형님이 매번 **뺐다.** 이 판에는 더하는 게 없다.

---

## §1 결론 먼저

**워크스페이스 툴은 조건 없이 준다. 결정 지점을 만들지 않는다.**

- 런은 **이미** 워크스페이스에 묶여 있다 (`product_id` → 워크트리). 표면을 좁힐 근거가 없다
- 읽기·조사는 위험하지 않다
- 무엇보다 — **"이 요청이 파일을 봐야 하나"는 프레임이 미리 맞힐 수 있는 것이 아니다.**
  에이전트가 열어봐야 아는 것이다. **그 예측을 강요한 것이 `c40c513d` 의 원인이다**

∴ `needs_workspace` 플래그(내 직전 제안)도 **폐기**한다. 새 타입 0개, **새 결정도 0개.**

---

## §2 그럼 무엇을 고치나 — `knowledge_only` 의 우회를 없앤다

지금 툴 표면을 정하는 자리는 함수 하나다:

```python
def mcp_tool_names_for(execution_target: str) -> tuple[str, ...]:
    if execution_target == "client_attach":
        return PLATFORM_TOOL_MCP_NAMES
    return WORK_TOOL_MCP_NAMES
```

**이 함수는 그대로 둔다.** 입력을 늘리지 않는다.

문제는 `knowledge_only` 가 **이 seam 을 아예 타지 않는 것**이다 —
`agent_runtime.py:247` 에서 `KnowledgeAnswerOrchestrator` 로 분기해 **툴 0개**로 답한다.

> `c40c513d` 가 추측으로 답한 이유는 "경로가 없어서"도 "플래그가 없어서"도 아니다.
> **툴 표면 seam 을 우회한 런이었기 때문이다.**

**고칠 것: 그 우회를 없앤다.** 워크스페이스가 있는 런은 전부 같은 seam 을 타고 같은 표면을 받는다.
단일-LLM-호출 비용 절감이 필요하면 **표면이 아니라 다른 축에서** 하라
(툴을 줬는데 안 쓰면 한 턴에 끝난다 — 굶기지 않아도 싸다).

## §3 남는 위험은 읽기가 아니라 쓰기다 — 그리고 이미 게이트가 있다

`FrameUnclassifiedError` 주석이 기록한 prod 사고 (실측 확인함):

| run | 의도 | 분류 | 결과 |
|---|---|---|---|
| `ff1615e8` | *"현 프로젝트 상황 설명해줘"* | `agent_loop` | **shipped** — 무관한 diff 가 나갔다 |

**순수 질문이 diff 를 내보냈다.** 하지만 그 원인은 **파일을 읽어서**가 아니라
**쓰고 내보내서**다. 읽기 표면을 넓히는 것과 무관한 사고다.

그리고 쓰기 쪽은 이미 게이트가 셋이다:

1. **B7 선언 게이트** — 선언 없이는 `file_write`/`file_edit` 거부 (`tools/__init__.py:605,648`)
2. **검증** — 선언된 command 의 exit code 가 판정
3. **Safe Mode 승인** — 파운더가 디프를 보고 판정, 그 후 PR + CI

∴ **쓰기를 툴 표면에서 또 막을 이유가 없다.** 사고는 표면이 아니라 **브리핑**에서 막는 것이 맞다 —
ASK 면 *"산출물을 만들지 말고 답하라"* 를 지시에 넣으면 된다. 이건 툴이 아니라 프롬프트다.

---

## §4 검증은 손대지 않는다

> **형님**: *"검증 때는 LLM Judge 제외하면 전부 정적, 결정적인 행위들을
> 실제 작업 전에 미리 테스트 파일처럼 정의하는거고"*

이미 그렇게 돼 있다 — `declare_verification` 이 작업 **전에** 선언하고,
쓰기 툴은 선언 전까지 거부되며(B7 #130), 선언된 command 는 **exit code 가 판정**이다.
LLM Judge 만 비결정적이고 그건 이미 분리돼 있다.

> **툴 표면과 검증은 직교한다. 서로를 파생시키지 않는다.**
> 내가 능력 모델에 넣었던 *"쓰기 능력이 있을 때만 검증 사다리 진입"* 규칙은 불필요하다 —
> 안 썼으면 선언할 것도 돌릴 것도 없다.

| 1 | `inspect_only` 세 번째 라벨 | *"복합적으로 쓰는 경우는 대응이 안되잖아"* — 고정 묶음만 하나 늘 뿐 |

> 그리고 **툴을 안 주면 에이전트는 실패하지 않고 추측한다** — 그게 `c40c513d` 다.
